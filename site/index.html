One privacy boundary, verified.

Nebula masks credentials, personal data and local paths inside a Hermes session, then restores only the tokens that have a documented local use. It is evidence for one pinned host commit and the paths tested there, not a claim about every laptop or provider.

Where the boundary sits

The plugin owns masking and local restoration. The pinned host owns enforcement.

CoveredSession-local masking of PII, credentials and paths; held-output redaction; fail-closed required mode on the pinned core.
Not coveredDirect tool or service traffic, MCP, media generation, unknown encodings, persisted prompts, UI and logs, or unsupported provider transports.
OwnershipHost enforcement, lifecycle and execution guarantees live in the Hermes core fork, not in this plugin.

What was actually tested

A green run is evidence only for the paths it exercised. Read the audit before installing.

  • CI audit — unit tests, dependency floors, secret scan, pinned-host E2E.
  • Versioning and releases — workflow lands before badge; merging is not a release.
  • Pinned host fork — required mode needs commit 9a85916.

Registered skills

Four skills ship with the plugin and register on hosts with the native skill API.

  • privacy-mask-placeholders — work inside the mask/restore mapping.
  • redacted-output-handling — interpret held and redacted output.
  • nebula-plugin-setup — install and configure the plugin.
  • nebula-plugin-debug — diagnose a policy denial or missing protection.

Install and migrate

Clone the repository to the path the sync script expects, then restart the process and start a new session.

git clone https://github.com/Abelion512/AHP.git \
  "$HOME/.hermes/abelion-hermes-plugins"
cd "$HOME/.hermes/abelion-hermes-plugins" && ./update-plugins.sh

Read the migration procedure before upgrading an existing profile.

Static documentation. No telemetry, no external assets. Merging a pull request does not install the plugin or publish a release.
