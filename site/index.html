Abelion Hermes Plugins STELLARIUM / PLATFORM

Plugins with explicit boundaries.

A monorepo for standalone Hermes Agent plugins. Each plugin owns its behavior, docs, skills and tests. CI runs against a pinned core commit and publishes evidence for the paths it exercised, not a claim about every host or provider.

Plugin manifest

hermes.json  ->  plugins/<id>/plugin.yaml
             ->  skills/<id>/SKILL.md
             ->  tests/ + e2e/

One catalog entry, one plugin folder, one docs trio, one test surface.

Discover

The catalog names the active plugins; each folder carries its own manifest.

Verify

Unit tests, contract checks and pinned-host E2E produce evidence per plugin.

Sync

The updater installs exactly the catalog entries into a Hermes profile.

Where the boundary sits

Each plugin owns its behavior. The pinned host owns enforcement, and the repository owns the evidence.

Plugin owns

Behavior, docs trio, skills, unit tests, E2E contract, and honest limits.

Host owns

Provider and tool interception, session lifecycle, held-stream semantics, and mandatory policy gates.

CI owns

Syntax, dependency audit, secret scan, plugin contract, real-host E2E against each declared pin.

What was actually tested

A green run is evidence only for the paths it exercised. Read the audit before installing a plugin.

  • CI audit Unit tests, dependency floors, secret scan, plugin contract, pinned-host E2E.
  • Versioning and releases Workflow lands before badge; merging is not a release.
  • Pinned host fork Required privacy mode depends on a reviewed host commit.

Install and migrate

Clone the repository to the path the sync script expects, then restart the process and start a new session.

git clone https://github.com/Abelion512/Stellarium.git \
  "$HOME/.hermes/abelion-hermes-plugins"
cd "$HOME/.hermes/abelion-hermes-plugins" && ./update-plugins.sh

Read the migration procedure before upgrading an existing profile.
